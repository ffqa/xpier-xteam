# xteam Kanban 看板与交互控制台开发进展总结

本文档沉淀 `xteam` 在 `v0.2.11 ~ v0.2.15` 版本中关于 **交互式看板退格防穿透**、**5 列敏捷泳道（Kanban TUI）** 及 **0-Token 交互控制台** 的架构设计、核心技术方案与开发进度记录。

---

## 1. 业务背景与问题分析

### 1.1 问题一：输入流控制字符穿透与退格失效（v0.2.13 解决）
- **现象**：用户在 `xteam board` 交互输入框中进行输入与删除操作时，出现 `ym\x7f\x7fym\x7f\x7f\x7f` 控制字符回显，已输入的字符未能成功删除，导致输入框堆积大量无效脏字符。
- **根因分析**：
  1. **按键流粘包**：在原生 TTY 终端 `cbreak` 或 `raw` 模式下，快速输入、中文输入法（IME）确认或退格时，单次 `sys.stdin.read(1)` 或 `os.read()` 经常收到多字节切片（如 `\x7f`、`\x08` 或 ANSI 转义序列 `\x1b[D`）。
  2. **逻辑退格与渲染不同步**：原有逻辑直接对输入进行盲追加或粗暴退格，缺乏行内光标索引（`cursor_idx`）概念；当遇到无法识别的控制码时，原样塞入了输入缓冲区 `buf`，导致屏幕回显乱码。
  3. **终端回退擦除不彻底**：退格时未向终端发出对应物理字符宽度的 `\b \b` 擦除序列，在多字节/全角字符退格时产生残影。

### 1.2 问题二：纵向列表与敏捷协同体验脱节（v0.2.14 ~ v0.2.15 解决）
- **现象**：原版 `xteam board` 采用纵向平铺文本流，团队角色、待办切片、闭合切片信息杂糅在一起，难以快速纵览端到端流动瓶颈。
- **目标**：参考现代终端 TUI 体验（如 Linear / Jira 看板），重构为标准 **5 列泳道看板**（`Backlog` ➔ `Todo` ➔ `Working` ➔ `Review` ➔ `Done`），同时保持 **纯 Python 标准库零依赖** 与 **0-Token 物理门铃直投**。

## 2. 核心架构与技术实现

### 2.1 状态驱动的 5 列敏捷泳道模型

看板完全从 xteam 协议底层的目录结构和切片生命周期中动态提取状态：

```
xteam 协作生命周期流转
┌─────────────────┐      ┌───────────────┐      ┌─────────────────┐      ┌────────────────┐      ┌─────────────────┐
│   1. Backlog    │ ───> │    2. Todo    │ ───> │   3. Working    │ ───> │   4. Review    │ ───> │     5. Done     │
├─────────────────┤      ├───────────────┤      ├─────────────────┤      ├────────────────┤      ├─────────────────┤
│ .xteam/QUEUE.md │      │ tasks/<slice>/│      │ tasks/<slice>/  │      │ tasks/<slice>/ │      │ .xteam/closed/  │
│ 待规划需求项    │      │ spec 编制中   │      │ dev 实现中      │      │ TL/Chase 验收中│      │ 已完成归档切片  │
└─────────────────┘      └───────────────┘      └─────────────────┘      └────────────────┘      └─────────────────┘
```

1. **Backlog**：解析 `.xteam/QUEUE.md`，提取待规划需求项（支持展示优先级与复杂度标记）；
2. **Todo**：PM 已立项但未进入 dev 编码的切片（草案期、TL spec 编制期）；
3. **Working**：Dev 正在实现中（活跃切片，高亮展示当前 Agent、运行时长 ⏱、执行检查项）；
4. **Review**：Dev 编码完成（`delivered.json` 已产出），等待 TL/Gate 终审裁决；
5. **Done**：已关闭并合入归档的切片（`.xteam/closed/<slice>`，支持统计折叠与最近交付摘要）。

### 2.2 纯 Python 标准库终端渲染引擎

在不引入 `curses`、`urwid` 或 `textual` 等外部重量级依赖的前提下，实现像素级对齐的终端 TUI：

#### 1) 物理显示列宽计算引擎 (`_cell_len`, `_fit_cell`, `_pad_cell`)
- 终端中汉字、全角标点、Emoji 占 2 个物理列宽，而 ASCII 字符占 1 个物理列宽。
- 使用 `unicodedata.east_asian_width(ch)`：
  - 若属于 `'W'` 或 `'F'`，则物理宽度为 2；
  - 其余字符宽度为 1。
- 文本截断（`_fit_cell`）和空格填充（`_pad_cell`）均基于物理列宽严格对齐，彻底根除了终端中英文混排边框错位和撕裂。

#### 2) 响应式宽度自适应（Responsive Layout）
- **宽屏 / 标准终端（列宽 $\ge 70$）**：完整并排渲染 5 列泳道卡片。
- **极窄屏（列宽 $< 70$）**：自动优雅降级为单列纵向卡片列表，防止换行溢出破坏终端视图。
- **命令行参数支持**：
  - `xteam board`：默认进入交互式 5 泳道看板；
  - `xteam board --list`：显式强制使用紧凑列表模式；
  - `xteam board --kanban`：显式强制使用 5 泳道看板模式；
  - `xteam board --once`：单次快照输出（保持经典脚本与 E2E 兼容性）。

### 2.3 流式防穿透按键事件处理器 (`process_board_keystrokes`)

位于 `bin/xteam_lib.py`：
- **逐字符状态机消费**：彻底解决多字节粘包，杜绝 `\x7f`、`\x08` 控制码穿透进文本缓冲区。
- **全套行内编辑体验**：
  - **Backspace (`\x7f`, `\x08`)**：精确删除光标前 1 个字符，光标左移。
  - **Delete (`\x1b[3~`)**：精确删除光标当前所在字符。
  - **左右方向键 (`\x1b[D`, `\x1b[C`)**：在缓冲区内精确移动 `cursor_idx`。
  - **Home / End / Ctrl+A / Ctrl+E**：瞬间跳至行首或行尾。
  - **Ctrl+U / Ctrl+K**：清除整行或清除光标后所有内容。
  - **Tab 键**：无感知循环轮换指令发送角色（`dev` ➔ `tl` ➔ `pm` ➔ `dev`）。
  - **Up / Down 方向键**：在历史命令记录 `cmd_history` 中上下回溯浏览。
- **终端实心光标渲染**：
  - 在当前 `cursor_idx` 位置的字符采用反白背景高亮（`\033[7m`），若光标在行尾则显示实心方块 `█`。

## 5. 后续演进路线

1. **泳道交互导航（Vim 键位）**：
   - 支持快捷键 `h/l`（左右）在泳道间切换高亮焦点，`j/k`（上下）在泳道内卡片间滚动；
   - 按 `Enter` 键直接查看选中卡片的切片详情或实时日志。
2. **切片直接操作**：
   - 支持在看板中对选中卡片一键发起 `:chase` 催促或 `:reject` 打回。
3. **Web / IDE 同步**：
   - Kanban 数据模型保持与 Web Dashboard 接口数据同构，便于未来提供跨终端视图。

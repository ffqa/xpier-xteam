# xteam Kanban TUI 多列泳道看板设计方案

本方案参考经典终端任务看板（如 Kander / Linear TUI），将 `xteam board` 从目前的纵向文本流重构为**横向 5 列敏捷泳道卡片流**，同时保留并深化底部的 0-Token 交互指令输入控制台。

## 2. 界面区域划分与信息架构

```
┌────────────────────────────────────────────────────────────────────────────────────────┐
│ 顶部状态条: xteam Board       Roles: PM (working 82%) | TL (idle) | Dev (working 45%)   │
├─────────────┬─────────────┬──────────────────────────┬─────────────┬───────────────────┤
│  Backlog 2  │   Todo 1    │        Working 1         │  Review 1   │      Done 28      │
│ ╭─────────╮ │ ╭─────────╮ │ ╭──────────────────────╮ │ ╭─────────╮ │ ╭───────────────╮ │
│ │ slice-4 │ │ │ slice-1 │ │ │ slice-4: fix-ime     │ │ │ slice-3 │ │ │ 20:30 d4e1c2b │ │
│ │ 待规划项│ │ │ 待分解  │ │ │ dev (omp) ⏱ 12m      │ │ │ 验收中  │ │ │ 已闭合交付    │ │
│ ╰─────────╯ │ ╰─────────╯ │ │ - 按键穿透与退格      │ │ ╰─────────╯ │ ╰───────────────╯ │
│             │             │ ╰──────────────────────╯ │             │ ▾ groups (3)      │
├─────────────┴─────────────┴──────────────────────────┴─────────────┴───────────────────┤
│ [发给 dev] ❯ 请修复 IME 退格与按键穿透问题█                                             │
│ XTEAM · android_dev | 5 cols | 31 slices                c chat | Tab role | :q | ?     │
└────────────────────────────────────────────────────────────────────────────────────────┘
```

### 1) 顶部栏 (Top Bar / HUD)
- **项目与更新时间**：左侧显示当前项目标签与看板名称，右侧显示本地刷新时间。
- **角色健康度仪表盘 (Role HUD)**：
  - PM、TL、Dev 三大角色的 Pane 实时运行态（`working` / `idle` / `blocked` / `draft`）；
  - 核心上下文占比（Context %），一旦接近告警阈值自动黄色/红色预警，提醒用户或触发 auto-rotate。

### 2) 中部 5 泳道卡片流 (Kanban Columns)
| 泳道名称 | 对应 xteam 协议生命周期 | 卡片展示重点 |
| :--- | :--- | :--- |
| **Backlog** | `.xteam/QUEUE.md` 中待开始的需求 | 需求标题、排期优先级、预估复杂度 |
| **Todo** | PM 已发起立项，但 TL 尚未完成 spec/decomp 的切片 | 需求草案、待制定技术契约 |
| **Working** | 当前 Dev 正在实现中（`tasks/<slice>` 处于 implement 状态） | 活跃切片名、负责 Agent（如 `omp`）、已耗时、进度检查项 |
| **Review** | Dev 已交付（`delivered.json` 就绪），TL 验收/Chase/Gate 窗口中 | 交付 diff 规模、测试结论、等待 verdict |
| **Done** | 已闭合交付（`verdict=PASS`，位于 `.xteam/closed/`） | 完成时间戳、责任人、commit hash 摘要、支持折叠历史组 |

### 3) 底部双模态指令控制台 (Bottom Console)
- **常驻/唤起输入栏**：
  - 支持快捷键 `c` 快速聚焦输入框（或默认常驻）；
  - 接入我们刚完成的行内光标、退格防穿透、左右方向键、Home/End、Delete；
  - `Tab` 键快速轮换目标角色（`[发给 pm]` ➔ `[发给 tl]` ➔ `[发给 dev]`）；
  - 回车一键触发 0-Token 门铃直投。
- **底栏状态行**：
  - 显示总切片数、当前列统计、快捷键操作帮助指南（`c chat` / `Tab role` / `:r refresh` / `:rotate <role>` / `:q exit`）。

## 3. 技术实现要点 (纯 Python 标准库零依赖)

1. **终端列宽自适应**：
   - 宽屏（$\ge 120$ 字符）：完整渲染 5 列并排泳道 Box；
   - 中屏（$90 \sim 119$ 字符）：合并/压缩 Backlog 与 Todo，保持主要 3~4 列；
   - 窄屏（$< 90$ 字符）：自适应折叠为单列/双列紧凑卡片流。
2. **纯 ANSI 盒子模型渲染器**：
   - 采用 `╭ ╮ ╯ ╰ │ ─` 字符实现轻量级终端盒子模型，无需依赖 curses 或 textual 庞大框架；
   - 各列卡片计算最大宽度与换行裁剪，保证无终端闪烁与错位。
